# labscripts — рабочие каталоги по ролям

В образе (`dist/alpine-tokb.ova`) этот каталог разложен как `/opt/labscripts`:

```
/opt/labscripts/
├── attacker/   ← то, что запускается на АТАКУЮЩЕЙ ВМ (192.168.56.20)
└── victim/     ← то, что запускается на ЖЕРТВЕ        (192.168.56.10)
```

Зачем разделение. Эталонный набор материалов лежит в `/opt/tokb` — там всё
вперемешку: и атакующие скрипты, и защитные. Студенту на конкретной ВМ нужна
только её половина, поэтому материалы разложены по ролям, а в каждом каталоге
лежит `README.md` с таблицей «этап работы → файл → команда».

**Файлы в `attacker/` и `victim/` — символические ссылки на `/opt/tokb`.**
Это сделано намеренно: будь это копии, студент неизбежно правил бы одну копию,
а запускал другую. Со ссылками любой путь — и `/opt/tokb/syn_scan.py`, и
`/opt/labscripts/attacker/syn_scan.py` — ведёт к **одному и тому же файлу**.

Образ один и тот же на обеих ВМ, поэтому оба каталога есть в любой из них:
работать нужно в том, который соответствует роли виртуалки.

Правка файлов — файловым менеджером `mc` (он же встроенный редактор), команды
`mc`, `mc -v <файл>`, `mc -e <файл>` и горячие клавиши — в README каждого
каталога и в Приложении В лабораторной работы.
